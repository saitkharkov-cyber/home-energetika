## Рабочий алгоритм одной категории

1. Зафиксировать прямой scope категории через `oc_product_to_category`.
2. `language_id = 1`.
3. Получить инвентаризацию реально используемых атрибутов.
4. Разбирать атрибуты по смысловым семействам.
5. Сначала сверяться с уже существующими канонами.
6. Новый канон создавать только при отсутствии подходящего существующего.
7. Исследовать распределение значений, единицы, дубли, конфликты и aliases.
8. Перед изменением делать preview.
9. Выполнять **одно ограниченное SQL-изменение за раз**.
10. После каждого изменения делать post-check.
11. После завершения характеристики обновлять канонический реестр и production log.
12. В конце выполнять полный аудит категории.

Единица измерения должна находиться в названии характеристики в скобках; в значении — только данные.

Глобальные определения атрибутов не удалять. Удалять только подтверждённые строки товаров в пределах прямого scope категории, когда это действительно необходимо.

## Что сейчас не делать

До отдельного решения не заниматься:

- дальнейшей разработкой Подборщика;
- заполнением `6026` пустых товаров;
- глобальной перегруппировкой атрибутов;
- созданием сложной админки канонических характеристик;
- отдельным Python/API-проектом автоматизации стандартизации;
- глобальной автоматической чисткой без ручного semantic review.

Группы характеристик проектировать после стандартизации основных товарных направлений, когда будет виден общий канонический набор.
